# BulkSend

**파일 개수 제한 없이** 같은 와이파이에 있는 폰끼리 사진·동영상·파일을 옮기는 앱입니다.

LocalSend 는 한 번에 999개까지만 보낼 수 있어서, 폰을 바꾸며 사진과 파일 수천 개를 옮기려고 직접 만들었습니다.
안드로이드 ↔ 아이폰 네 방향(안드→안드, 안드→아이폰, 아이폰→안드, 아이폰→아이폰)을 모두 지원합니다.

## 주요 기능

- **개수 제한 없음**: 목록을 1,000개 단위로 나눠 등록하고, 동시에 3개씩 업로드합니다.
- **이어받기**: 연결이 끊기면 받은 바이트 위치부터 이어서 보내고, 이미 받은 파일은 건너뜁니다. 앱을 다시 켜도 이어집니다.
- **6자리 인증번호 연결**: 받는 폰에 뜬 번호만 입력하면 연결됩니다. IP 를 몰라도 됩니다.
- **사진·동영상은 갤러리로, 파일은 폴더 구조 그대로**
  - 원본 파일(HEIC/MOV 등) 그대로 보내고, 촬영일을 유지합니다.
  - 폴더를 고르면 하위 폴더 구조와 한글 파일명을 그대로 옮깁니다.
- **전송 중 화면 켜짐 유지**, 앱이 백그라운드에 다녀오면 자동으로 이어서 보냅니다.
- **아이폰 파일·폴더 선택 시 복사 없음**: 고른 파일을 임시 폴더로 복사하지 않고 원본을 바로 읽습니다.

## 사용법

1. 두 폰을 **같은 와이파이**에 연결합니다. 공유기가 없으면 한쪽 폰의 핫스팟에 다른 폰을 연결해도 됩니다.
2. 받는 폰: **받기** → 화면의 6자리 번호를 확인합니다.
3. 보내는 폰: **보내기** → 사진 전체 / 앨범 / 파일 / 폴더 중에서 고릅니다(여러 번 골라 합칠 수 있음).
4. 번호를 입력하고 **전송 시작**. 전송이 끝날 때까지 두 폰 화면을 켜 둡니다.

연결이 끊기면 "재개"를 누르거나 같은 번호로 다시 보내면 이어서 전송됩니다.

### 저장 위치

| | 사진·동영상 | 파일·폴더 |
|---|---|---|
| 안드로이드 | 갤러리 (`DCIM/BulkSend`) | `Download/BulkSend` |
| 아이폰 | 사진 앱 | 파일 앱 › 나의 iPhone › BulkSend |

## 설치

스토어에 올리지 않은 개인용 앱이라 직접 빌드해서 설치합니다.

- Flutter 3.47 / Dart 3.13 (개발 환경 기준)
- 안드로이드

  ```bash
  flutter build apk --release
  adb install build/app/outputs/flutter-apk/app-release.apk
  ```

- 아이폰 (무료 Apple ID 로 설치 가능, 7일마다 다시 설치 필요)
  1. `ios/Runner.xcworkspace` 를 Xcode 로 엽니다.
  2. Runner › Signing & Capabilities 에서 **Team** 을 본인 계정으로 선택합니다.
  3. 폰을 연결하고 실행합니다.
  4. 폰의 설정 › 일반 › VPN 및 기기 관리에서 개발자를 **신뢰**합니다.

### 권한

- 안드로이드: **모든 파일 접근**(받은 파일 저장, 폴더 읽기), 사진·동영상 읽기(보내기)
- 아이폰: 사진 보관함 전체 접근, 로컬 네트워크

## 동작 방식

받는 폰이 HTTP 서버(포트 `53420`)를 열고, 보내는 폰이 파일을 업로드합니다.

```text
[보내는 폰]                                  [받는 폰]
 인증번호 입력 → 주소 계산                     6자리 번호 표시 (IP 끝자리 3 + PIN 3)
   POST /api/session              ───────▶   PIN 확인
   POST /api/session/{sid}/files  ───────▶   파일별 상태 응답 (완료 / 부분 + 오프셋 / 새 파일)
   PUT  /api/session/{sid}/upload/{id} ──▶   .part 임시파일에 이어 쓰기 → 다 받으면 저장 위치로 이동
   POST /api/session/{sid}/finish ───────▶   결과 요약
```

- **인증번호**: 앞 3자리는 받는 폰 IP 의 마지막 자리, 뒤 3자리는 랜덤 PIN 입니다. 보내는 폰은 자기 IP 의 앞 세 자리에 번호 앞 3자리를 붙여 주소를 만듭니다(두 폰이 같은 `/24` 대역이어야 함).
- **이어받기**: 받는 쪽은 보낸 기기별로 완료 기록(`done.log`)과 받던 파일(`.part`)을 남깁니다. 오프셋이 어긋나면 `409` 로 현재 위치를 알려주고, 보내는 쪽이 거기에 맞춰 다시 보냅니다.
- **크기를 모르는 사진**: 아이폰 사진은 원본을 꺼내 봐야 정확한 크기를 알 수 있어서, 크기 없이 등록하고 업로드할 때 `X-Size` 헤더로 알려줍니다. 그래서 이미 받은 사진은 꺼내지 않고 건너뜁니다.
- **안드로이드 촬영일 유지**: 갤러리 폴더에 직접 저장하고 파일 수정시각을 원래 날짜로 맞춘 뒤 미디어 스캔을 요청합니다. (MediaStore 로 넣으면 스캐너가 시간대 없는 EXIF 촬영일을 버리고, 앱이 DATE_TAKEN 을 고치는 것도 Android 11+ 에서 무시됩니다.)

## 프로젝트 구조

```text
lib/
├── core/                       # 플랫폼 독립 로직 (단위 테스트 대상)
│   ├── models.dart             # 전송 모델, 파일 ID
│   ├── receiver_server.dart    # 받는 쪽 HTTP 서버, 이어받기
│   ├── sender.dart             # 보내는 쪽: 배치 등록, 병렬 업로드, 재시도
│   ├── storage.dart            # 폴더 저장 (경로 정리, 이름 충돌, 수정시각 복원)
│   └── connect_code.dart       # 6자리 인증번호, 사설 IP 선택
├── platform/                   # 플랫폼별 저장소·소스
│   ├── receive_storage.dart    # 갤러리/폴더 저장, 권한
│   ├── send_sources.dart       # 파일·폴더·사진 라이브러리
│   └── device.dart
└── ui/                         # 홈 / 보내기 / 받기 화면
ios/Runner/AppDelegate.swift    # 복사 없는 파일·폴더 선택기 (보안 범위 접근 유지)
android/.../MainActivity.kt     # 미디어 스캔 요청 채널
```

## 테스트


프로토콜·이어받기·동시 수신 등 핵심 로직은 로컬 HTTP 서버로 테스트합니다. 앱 동작은 iOS 시뮬레이터·안드로이드 에뮬레이터(Maestro 자동화)와 실기기(Galaxy S21 Android 15 ↔ iPhone 12 Pro Max iOS 26.5)에서 확인했습니다. 실기기에서 1GB 파일을 약 15MB/s 로 보냈습니다.

## 알려진 제약

- 두 폰이 같은 `/24` 네트워크여야 합니다. 대역이 큰 회사 망 등에서는 연결되지 않을 수 있습니다.
- 전송 중에는 화면을 켜 두어야 합니다. 아이폰은 백그라운드로 가면 연결이 끊기고, 돌아오면 이어서 보냅니다.
- Live Photo 는 사진과 MOV 두 파일로 따로 보냅니다.
- EXIF 도 메타데이터도 없는 이미지·동영상은 안드로이드 갤러리 촬영일이 비고, 파일 수정시각만 원래 날짜로 남습니다.
- 인증번호의 PIN 은 3자리입니다. 개인용 앱이라 추측 방지 장치는 따로 두지 않았습니다.
